- This is part of local privilege escalation
- The sources that can provide us with credentials include but not limited to:
	- Files
	- History
	- Memory
	- Key-rings

### 1) Files
- We should inspect several categories of files one by one
- These categories are:
	- Configuration Files
	- Databases
	- Notes
	- Scripts
	- Cronjobs
	- SSH Keys
- Usually, configuration files are marked with following three extensions:
	- `.config`
	- `.conf`
	- `.cnf`

1. **Searching for Configuration Files**
	- `for l in $(echo ".config .conf .cnf"); do echo -e "\nFile extension: " $l; find / -name *$l 2>/dev/null | grep -v "lib\|fonts\|share\|core";done`
	- OR: `for i in $(find / -name *.cnf 2>/dev/null | grep -v "doc\|lib"); do echo -e "\nFile; " $i; grep "user\|password\|pass" $i 2>/dev/null | grep -v "\#"; done`

2. **Searching for Databases**
	- `for l in $(echo ".sql .db .*db .db*");do echo -e "\nDB File extension: " $l; find / -name *$l 2>/dev/null | grep -v "doc\|lib\|headers\|share\|man";done`

3. **Searching for Notes**
	- `find /home/* -type f -name "*.txt" -o ! -name  "*.*"`

4. **Searching for Scripts**
	- `for l in $(echo ".py .pyc .pl .go .jar .c .sh"); do echo -e "\nFile Extension: " $l; find / -name *$l 2>/dev/null | grep -v "doc\|lib\|headers\|share"; done`

5. **Enumerating Cronjobs**
	- Cronjobs are independant execution of commands, programs, scripts
		- These are divided into the system-wide are (`/etc/crontab`) and user-dependant executions
	- The scripts and files used by `cron` can also be found in `/etc/cron.d/` for Debian-based distributions
	- `cat /etc/crontab`
	- `ls -la /etc/cron.*/`

6. **Enumerating History Files**
	- For bash shells, we find history files in `.bash_history`, while other files like `.bashrc` or `.bash_profile` can contain important information
	- `tail -n5 /home/*/.bash*`

7. **Enumerating Log Files**
	- The entirety of log files can be divided into four categories:
		- Application logs
		- Event logs
		- Service logs
		- System logs

| **File**              | **Description**                                    |
| --------------------- | -------------------------------------------------- |
| `/var/log/messages`   | Generic system activity logs.                      |
| `/var/log/syslog`     | Generic system activity logs.                      |
| `/var/log/auth.log`   | (Debian) All authentication related logs.          |
| `/var/log/secure`     | (RedHat/CentOS) All authentication related logs.   |
| `/var/log/boot.log`   | Booting information.                               |
| `/var/log/dmesg`      | Hardware and drivers related information and logs. |
| `/var/log/kern.log`   | Kernel related warnings, errors and logs.          |
| `/var/log/faillog`    | Failed login attempts.                             |
| `/var/log/cron`       | Information related to cron jobs.                  |
| `/var/log/mail.log`   | All mail server related logs.                      |
| `/var/log/httpd`      | All Apache related logs.                           |
| `/var/log/mysqld.log` | All MySQL server related logs.                     |
- `for i in $(ls /var/log/* 2>/dev/null);do GREP=$(grep "accepted\|session opened\|session closed\|failure\|failed\|ssh\|password changed\|new user\|delete user\|sudo\|COMMAND\=\|logs" $i 2>/dev/null); if [[ $GREP ]];then echo -e "\n#### Log file: " $i; grep "accepted\|session opened\|session closed\|failure\|failed\|ssh\|password changed\|new user\|delete user\|sudo\|COMMAND\=\|logs" $i 2>/dev/null;fi;done`

**Mimipenguin**
- We can use a tool called `mimipenguin` to retrieve credentials information form Linux distributions
- `sudo python3 mimipenguin.py`

**LaZagne**
- Even more powerful tool than `mimipenguin`
- The passwords and hashes we can obtain come from the following sources but are not limited to:
	- Wifi
	- Wpa_supplicant
	- Libsecret

	- CLI

	- Thunderbird
	- Git
	- ENV variables
	- Grub
	- Fstab
	- AWS
	- Filezilla
	- Gftp
	- SSH
	- Apache
	- Shadow
	- Docker
	- Keepass
	- Mimipy
	- Sessions
	- Keyrings
- `sudo python2.7 LaZagne.py all`

**Browser Credentials**
- Browsers store the passwords used by users in encrypted form locally on the system to be reused
- For example, when we store credentials for a web page in the Firefox browser, they are encrypted in `logins.json` on the system
- `ls -l .mozilla/firefox/ | grep default`
- `cat .mozilla/firefox/[filename from the previous command's output] | jq .`
- The tool `Firefox Decrypt` is excellent for decrypting these credentials
	- It requires Python 3.9 to run the latest version
	- Otherwise, `Firefox Decrypt 0.7.0` with Python 2 must be used
- `python3.9 firefox_decrypt.py`
- Alternatively, `LaZagne` can also returns results if the user has used the supported browser
	- `python3 laZagne.py browsers`
