
**Module Structure:**
- `<type>/<os>/<service>/<name>` (e.g., exploit/windows/ftp/scriptftp_list)
- Type: Auxiliary, Encoders, Exploits, NOPs, Payloads, Plugins, Post
- Interactable modules (use command): Auxiliary, Exploits, Post
- OS: Operating system and architecture
- Service: Vulnerable service or general activity
- Name: Specific action performed

**Search Function:**
- `search <keywords>` — find modules by keyword
- Keywords: cve, type, platform, port, rank, author, description, fullname, date, check, arch, bid, edb, ref
- Filter by: `cve:2009 type:exploit platform:-linux` (exclude with -)
- Sort: `-s <column>` (rank, date, name, type, check)
- Reverse: `-r`
- Example: `search ms17_010` or `search type:exploit platform:windows cve:2021 rank:excellent`

**Module Selection & Options:**
- `use <no.>` — select module by index number from search results
- `options` — view required and optional settings
- Required column = "Yes" must be set before exploit
- `info` — detailed module information (provided by, platform, arch, references, description)
- `set <option> <value>` — set individual option
- `setg <option> <value>` — set option permanently (until restart)

**Key Options:**
- RHOSTS / RHOST — target host(s)
- RPORT — target port (default varies)
- LHOST — attacker IP (for reverse shells)
- LPORT — attacker listening port (default 4444)
- EXITFUNC — exit technique (seh, thread, process, none)
- Payload options — varies by payload type

**Execution:**
- `run` or `exploit` — launch the attack
- MSF handles: check method (vulnerability verification), connection, payload delivery, shell establishment
- Output shows progress, vulnerability confirmation, shell session opened
- `shell` — drop to system shell from meterpreter

**Key Concept:**
- MSF is a support tool, not a substitute for manual skills
- Exploit failure ≠ vulnerability doesn't exist (requires customization to target)
- Use `check` method before `run` when available
