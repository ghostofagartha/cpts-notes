- A module that aids the exploit module in (typically) returning a shell to the attacker
- Sent together with the exploit itself to bypass standard functioning procedures of the vulnerable service (exploits job)
- Run on the target OS to typically return a reverse connection to the attacker and establish a foothold (payload's job)

****
### Types of Payloads
- Singles
- Stagers
- Stages
1. **Singles**
	- Contains the exploit and the entire shellcode for the selected task
	- Most stable
	- Not supported by some exploits, as they can get large in size
	- Self-contained payloads
2. **Stagers**
	- Work together with **Stages**
	- Runs on the victim machine and initiates an outbound connection to the attacker's listener, setting up the communication channel over which the subsequent stage payload is delivered
	- Typically small and reliable
3. **Stages**
	- Payload components that are downloaded by stager's modules
	- Provide advanced features with no size limits, such as Meterpreter, VNC Injection, and others
	- Payload stages automatically use middle stagers:
		- A single **recv()** fails with large payloads
		- The Stager receives the middle stager
		- The middle Stager then performs a full download
		- Also better for RWX

****
### Staged Payloads
- An exploitation process that is modularized and functionally separated to help segregate the different functions it accomplishes into different code blocks, each completing its objective individually but working on chaining the attack together
- Scope of this payload is to grant shell access to the target system and to be as compact and inconspicuous as possible to aid with the Antivirus (AV) / Intrusion Prevention System (IPS) evasion as much as possible
#### Stage0
- Stage0 of a staged payload represents the initial shellcode sent over the network to the target machine's vulnerable service, which has the sole purpose of initializing a connection back to the attacker machine
	- Common names for these in Metasploit are
		- **reverse_tcp**
		- **reverse-https**
		- **bind_tcp**

##### Meterpreter Payload
- Provides a specific type of multi-faceted payload that uses **DLL Injection** to ensure the connection to the victim host is stable, hard to detect by simple checks, and persistent across reboots or system changes
- Meterpreter resides in memory only and leaves no trace on the hard drive

****
### Searching for Payloads
#### MSF - List Payloads
- `show payloads`
#### MSF - Searching for Specific Payload
- `grep meterpreter show payloads`  or `grep meterpreter grep reverse_tcp show payloads`

****
### Selecting Payloads
#### MSF - Select Payload
- `use [index number]`
- `show payloads`
- `set payload [no.]`

### Payload Types

| Payload Type                      | Purpose                                              |
| --------------------------------- | ---------------------------------------------------- |
| `generic/custom`                  | Custom payload handler, multi-use listener           |
| `generic/shell_bind_tcp`          | Normal shell using a bind TCP connection             |
| `generic/shell_reverse_tcp`       | Normal shell using a reverse TCP connection          |
| `windows/x64/exec`                | Executes an arbitrary command on Windows x64         |
| `windows/x64/loadlibrary`         | Loads an arbitrary x64 library (DLL)                 |
| `windows/x64/messagebox`          | Displays a Windows message box                       |
| `windows/x64/shell_reverse_tcp`   | Single payload, normal shell, reverse TCP connection |
| `windows/x64/shell/reverse_tcp`   | Staged normal shell, reverse TCP connection          |
| `windows/x64/shell/bind_ipv6_tcp` | Staged normal shell, IPv6 bind TCP connection        |
| `windows/x64/meterpreter/$`       | Meterpreter payload variants                         |
| `windows/x64/powershell/$`        | Interactive PowerShell session variants              |
| `windows/x64/vncinject/$`         | VNC remote desktop payload variants                  |
